# 四柱推命鑑定サイト（かりん）

Next.js（App Router）+ microCMS で作られた、スマートフォン向けの1ページ完結型サイトです。白×ピンクの優しいトーンでまとめています。

- 開発者（あなた）がソースコードを管理します
- かりんさんは microCMS の管理画面から「お知らせ・ブログ」「写真ギャラリー」「鑑定メニュー・料金」「プロフィール」「スケジュール」を投稿・編集できます
- 投稿すると、コードを触らずに自動でサイトに反映されます（ISR + Webhook）
- お問い合わせ・ご予約フォームも設置済み（Web3Formsという無料サービス経由でメール受信、月250件まで無料）
- 一般の閲覧者は記事や写真を見るだけで、編集はできません（編集画面はmicroCMS側にあり、サイト上には存在しません）

### 全体構成（システムの流れ）

このサイトは、大きく分けて3つの仕組みが連携して動いています。

1. **microCMS**（コンテンツ管理）— かりんさんが記事や写真、スケジュールなどを入力・保存する場所です。管理画面はmicroCMS側にあり、このリポジトリのコードには含まれません。
2. **Next.js（このコード）+ Vercel**（Webサイト本体）— microCMSからデータを取得して、実際に閲覧者へ表示するホームページです。ソースコードはGitHubで管理し、Vercelが自動でビルド・公開します。
3. **Web3Forms**（お問い合わせフォームの送信先）— サイト内のフォームから送信された内容を、指定したメールアドレスへ転送してくれる無料サービスです。サイト側にメールサーバーは持ちません。

データが反映されるまでの流れはこうなります。

```
[かりんさん] --microCMS管理画面で入力・公開-->
[microCMS] --Webhook通知--> [/api/revalidate（このコード内）] --キャッシュを再生成-->
[Next.js（Vercel上で稼働中）] --REST APIで取得したデータを元に表示--> [サイトを見る人のブラウザ]
```

Webhookが届かなくても、60秒ごとに自動でmicroCMSの最新データを取りに行く仕組み（ISR）が入っているため、最悪でも1分程度で反映されます。Webhookを設定すると、公開した瞬間にほぼ即座に反映されます（詳しくは「5. 自動反映（Webhook）を設定する」を参照）。

お問い合わせフォームは上記の流れとは別で、以下のように動きます。

```
[サイトを見る人] --フォーム送信--> [Web3Forms] --メール転送--> [かりんさん（またはあなた）の受信メール]
```

技術面のまとめ:

- フロントエンド: Next.js（App Router）+ React + TypeScript
- スタイル: 素のCSS（`src/app/globals.css`。CSSフレームワークは使っていません）
- コンテンツ管理: microCMS（無料プランのAPI数上限5個をすべて使用: menu / profile / news / gallery / schedule）
- ホスティング: Vercel（無料Hobbyプラン）
- アクセス解析: Vercel Web Analytics（無料。月5万イベントまで、Hobbyプランでは超えても課金されず一時停止するだけ）
- お問い合わせフォームの送信先: Web3Forms（無料プラン。月250件まで）
- ページ構成: `/`（ホーム）1ページのみで、別ページや管理画面はこのコード内には存在しません

### ページ構成

タブや別ページには分けず、すべて `/`（ホーム）内のセクションとして1画面に表示し、アンカーリンクでスクロール移動する構成です。

| セクション（id） | 内容 | データの出どころ |
|---|---|---|
| ヒーロー | プロフィール写真・キャッチコピー | profile |
| `#radio` ラジオ出演 | 自己紹介・SNSリンク・ラジオ番組情報（放送中バッジ／次回放送日／過去の放送アーカイブ） | profile |
| `#menu` 鑑定メニュー | 鑑定メニュー・料金一覧 | menu |
| `#schedule` スケジュール | 日付ごとの状態が色分けされたカレンダー | schedule |
| `#news` お知らせ | お知らせ・ブログ | news |
| `#gallery` ギャラリー | 写真ギャラリー | gallery |
| `#contact` お問い合わせ | お問い合わせ・ご予約フォーム | Web3Forms |

## 1. まず microCMS 側を準備する

### 1-1. サービスを作成

1. https://microcms.io/ で無料アカウントを作成
2. 「サービスを作成」→ サービスID（例: `karin`）を決める
   - このサービスIDが後で環境変数 `MICROCMS_SERVICE_DOMAIN` になります

### 1-2. APIを5つ作成する

無料のHobbyプランはAPI数の上限が5個のため、ちょうど上限いっぱいまで使う構成です。

**① 鑑定メニュー・料金 用のAPI**

- **エンドポイント名: `menu`**（必ずこの名前）
- 型: リスト形式
- フィールド:

| フィールドID | 表示名 | 種類 | 必須 |
|---|---|---|---|
| `title` | メニュー名 | テキストフィールド（例: `対面鑑定`） | ○ |
| `price` | 料金 | テキストフィールド（例: `¥8,000（税込）`） | ○ |
| `time` | 鑑定時間 | テキストフィールド（例: `30分`） | - |
| `description` | 説明 | テキストエリア（複数行） | - |

> メニュー名と料金は必須、鑑定時間・説明は任意です（鑑定時間は未入力だと一覧に表示されません／説明は未入力だとモーダルに「説明はありません。」と表示されます）。表示順は自動的に料金の安い順になります（料金欄の数字部分だけを見て並び替えるので、「¥8,000（税込）」のような自由な書き方のままで大丈夫です）。各メニューをクリックすると、メニュー名・料金・鑑定時間・説明を表示するモーダルが開きます。

**② プロフィール（ラジオ出演情報を含む） 用のAPI**

- **エンドポイント名: `profile`**（必ずこの名前）
- **型: オブジェクト形式**（この1種類のAPIだけは「リスト形式」ではなく「オブジェクト形式」を選んでください）
- フィールド:

| フィールドID | 表示名 | 種類 | 必須 |
|---|---|---|---|
| `name` | お名前 | テキストフィールド | ○ |
| `catchCopy` | キャッチコピー | テキストフィールド（例: `四柱推命鑑定士`） | - |
| `photo` | 写真 | 画像 | - |
| `bio` | 自己紹介・経歴（ラジオコーナーの一言コメントもここに） | リッチエディタ | ○ |
| `instagramUrl` | InstagramのURL | テキストフィールド | - |
| `lineUrl` | 公式LINEのURL | テキストフィールド | - |
| `radioUrl` | ラジオ番組ページのURL | テキストフィールド（放送中バッジと「ラジオ」ボタンのリンク先） | - |
| `radioProgramName` | ラジオ番組名 | テキストフィールド（例: `華鈴の未来予想図`） | - |
| `radioStation` | 放送局 | テキストフィールド（例: `ゆめのたね放送局（グリーンチャンネル）`） | - |
| `radioScheduleText` | 放送日時の表示文言 | テキストフィールド（例: `毎週木曜日 21:30〜22:00`） | - |
| `radioArchive` | 過去の放送 | 繰り返し（下記のカスタムフィールドを使用） | - |

> `radioArchive`は、まず「カスタムフィールド」メニュー（APIの一覧とは別の場所にあります。APIの上限5個にはカウントされません）で、フィールドID `radioArchiveItem` として次の3つを作成してください。
>
> | フィールドID | 表示名 | 種類 | 必須 |
> |---|---|---|---|
> | `broadcastDate` | 放送日 | 日付（時刻の指定なしでOK） | ○ |
> | `audioUrl` | 音声ファイルのURL | テキストフィールド | ○ |
> | `title` | 補足タイトル | テキストフィールド | - |
>
> 作成後、profile APIのスキーマで新規フィールドを追加し、種類を「繰り返し」にして、このカスタムフィールド（`radioArchiveItem`）を選択してください。フィールドID: `radioArchive`、表示名: `過去の放送`。
>
> **放送中バッジ・次回放送日の表示ロジックについて**: 「毎週木曜21:30〜22:00」を`src/lib/format.ts`の定数（`RADIO_ON_AIR_WEEKDAY` / `RADIO_ON_AIR_WEEKDAY_INDEX` / `RADIO_ON_AIR_START_MINUTES` / `RADIO_ON_AIR_END_MINUTES`）に固定で持たせています。放送の曜日・時間が変わった場合は、`radioScheduleText`（表示用の文言）と一緒に、この定数も必ず更新してください（表示文言だけ直してコード側を直し忘れると、バッジの表示タイミングと文言がズレます）。

**③ お知らせ・ブログ用のAPI**

- **エンドポイント名: `news`**（必ずこの名前）
- 型: リスト形式
- フィールド:

| フィールドID | 表示名 | 種類 | 必須 |
|---|---|---|---|
| `title` | タイトル | テキストフィールド | ○ |
| `instagramUrl` | Instagramの投稿URL | テキストフィールド | - |
| `content` | 本文 | リッチエディタ | - |
| `eyecatch` | アイキャッチ画像 | 画像 | - |
| `category` | カテゴリ | セレクトフィールド（選択肢: `お知らせ` / `ブログ` / `イベント`） | - |

> 表示される日付は、入力欄ではなく「公開した日時」が自動的に使われます。日付を入力する手間はありません。
>
> `instagramUrl` と `content` はどちらも必須ではありませんが、最低どちらか一方は入力してください。Instagramの投稿をそのまま紹介したい時は`instagramUrl`だけ、サイト内に文章を書きたい時は`content`だけでOKです。**両方入力した場合はInstagramへのリンクが優先され、本文は表示されません。**
>
> サイトのお知らせ欄には最初5件だけ表示され、「もっと見る」を押すとそれ以降（最大20件）も表示されます。

**④ 写真ギャラリー用のAPI**

- **エンドポイント名: `gallery`**（必ずこの名前）
- 型: リスト形式
- フィールド:

| フィールドID | 表示名 | 種類 | 必須 |
|---|---|---|---|
| `title` | タイトル | テキストフィールド | ○ |
| `image` | 写真 | 画像 | ○ |
| `description` | 説明 | テキストエリア | - |

> ギャラリーはサムネイルが3列で並び、最初は2行分（6件）だけ表示されます。7件目以降がある場合は「もっと見る」で残りが表示されます。写真をタップすると拡大表示され、タイトルと説明が別の行で表示されます。

**⑤ スケジュール 用のAPI**

日付ごとに状態を登録すると、カレンダーに自動で色分け表示されます。

- **エンドポイント名: `schedule`**（必ずこの名前）
- 型: リスト形式
- フィールド:

| フィールドID | 表示名 | 種類 | 必須 |
|---|---|---|---|
| `date` | 日付 | 日付（年月日のみでOK） | ○ |
| `startTime` | 開始時刻 | テキストフィールド（例: `13:00`。24時間表記で入力） | - |
| `endTime` | 終了時刻 | テキストフィールド（例: `17:00`。24時間表記で入力） | - |
| `label` | 補足の短い文言 | テキストフィールド（例: `マルシェ` `講座` など。時間以外に書きたいことがあれば） | - |
| `type` | 区分（色分け用） | セレクトフィールド（選択肢: `鑑定可` / `不可` / `イベント`） | ○ |
| `note` | 補足 | テキストエリア | - |

> カレンダーには「開始時刻〜終了時刻 ラベル」の形（例: `13:00〜17:00 マルシェ`）で自動的に表示されます。開始・終了時刻とラベルはどちらも空欄でも構いません（その場合は区分名だけが表示されます）。
>
> 色分けの対応: `鑑定可` = ピンク（対応可能）／`不可` = グレー（対応不可）／`イベント` = ゴールド（出張・イベント等）

> フィールドを増やしたくなった場合は、`src/types/microcms.ts` の型定義と、表示側のコード（`src/app/page.tsx` や `src/components` 配下）も合わせて修正してください。

### 1-3. APIキーを発行

「サービス設定」→「APIキー」から、GET権限のあるAPIキーを発行し、控えておきます。
（環境変数 `MICROCMS_API_KEY` になります）

### 1-4. かりんさん用のログインアカウントを作成

「サービス設定」→「メンバー」からメールアドレスを招待します。
権限は「編集者」など、コンテンツの作成・編集ができる権限を付与してください（サービス設定自体はいじれない権限にしておくと安全です）。

### 1-5. プロフィールを1件だけ作成しておく

`profile` はオブジェクト形式なので、公開前に一度だけ内容を入力して「公開」しておいてください（未公開だとサイト側に「準備中」と表示されます）。

## 2. お問い合わせフォームの送信先を用意する（Web3Forms）

サーバーやメールの設定なしで、無料でフォーム送信をメール通知できる仕組みです（無料枠: 月250件まで）。

1. https://web3forms.com/ にアクセスし、受信したいメールアドレスを入力して「Create Access Key」
2. 届いたメールのリンクからアクセスキーを有効化し、キーをコピー
3. これが環境変数 `NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY` になります

## 3. コードを手元で動かす

```bash
npm install
cp .env.local.example .env.local
```

`.env.local` を開き、以下を実際の値に書き換えます。

```
MICROCMS_SERVICE_DOMAIN=（1-1で決めたサービスID）
MICROCMS_API_KEY=（1-3で発行したAPIキー）
REVALIDATE_SECRET=（好きなランダム文字列。他人に推測されないもの）
NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY=（2で発行したアクセスキー）
```

起動:

```bash
npm run dev
```

http://localhost:3000 をスマートフォンの画面サイズ（開発者ツールでデバイス表示に切り替えると見やすいです）で確認してください。

## 4. Vercelにデプロイする（無料）

1. このプロジェクトをGitHubリポジトリにpush
2. https://vercel.com/ でGitHubアカウント連携してインポート
3. 環境変数（`MICROCMS_SERVICE_DOMAIN` / `MICROCMS_API_KEY` / `REVALIDATE_SECRET` / `NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY`）をVercelのプロジェクト設定 → Environment Variables に追加
4. デプロイすると `https://プロジェクト名.vercel.app` のようなURLが発行されます

> 個人・非商用利用であればVercelの無料Hobbyプランの範囲内で運用できますが、鑑定業として収益が発生する事業サイトの場合はVercelの利用規約上Proプラン(有料)が必要になるケースがあります。利用規約は運用開始前にご確認ください。

## 5. 自動反映（Webhook）を設定する

投稿してから最大60秒ほどで自動的に反映される仕組み（ISR）が既に組み込まれていますが、
「保存した瞬間に反映したい」場合は、microCMS側でWebhookを設定します。

1. microCMSの対象APIの管理画面 →「API設定」→「Webhook」
2. 以下のURLを登録:
   ```
   https://あなたのVercelのURL/api/revalidate?secret=REVALIDATE_SECRETに設定した値
   ```
3. トリガーは「コンテンツ公開時」「コンテンツ更新時」「コンテンツ削除時」すべてにチェック
4. `menu` / `profile` / `news` / `gallery` / `schedule` の5つのAPIすべてに同じ設定をします

これで、かりんさんが投稿を保存した瞬間にサイトへ反映されるようになります。

## 6. かりんさん向けの使い方（メモとして渡す用）

かりんさん向けの詳しい操作マニュアル（Wordファイル）を別途用意しています。各コンテンツ（お知らせ・ギャラリー・メニュー・プロフィール・スケジュール・ラジオの過去放送）の追加・編集手順をまとめてあるので、そちらを渡してください。

簡単にまとめると、流れは次のとおりです。

1. microCMSの管理画面URL（`https://サービスID.microcms.io` の管理画面）にログイン
2. 更新したいAPI（お知らせ／ギャラリー／メニュー／プロフィール／スケジュール）を選んで「追加」または既存コンテンツを選択
3. 内容を入力
4. 右上の「公開」ボタンを押す
5. 数十秒待ってからホームページを開くと反映されています（Webhook設定済みなら、ほぼ即座に反映されます）

お問い合わせフォームからの連絡は、Web3Forms登録時のメールアドレス宛に直接届きます。

## 8. デザインについて

`src/app/globals.css` に白×ピンクの配色（CSS変数）をまとめています。色味を変えたい場合は `:root` 内の `--color-*` を変更するだけで全体に反映されます。

## 9. アクセス解析（Vercel Web Analytics）を有効にする

コード側の設定（`@vercel/analytics`パッケージの追加、`app/layout.tsx`への`<Analytics />`設置）は済んでいます。あとはVercel側で有効化するだけです。

1. `npm install` を実行して依存パッケージ（`@vercel/analytics`）を取得する
2. Vercelのダッシュボード → 対象プロジェクト → 「Analytics」タブ → 「Enable」を押す
3. 通常どおりデプロイする（新しく`/_vercel/insights/*`というルートが追加されます）
4. 数日間、実際に訪問者が来たあとに、同じ「Analytics」タブでアクセス数などのデータを確認できます

無料のHobbyプランでは月5万イベント（ページ表示など）まで無料で、それを超えても課金はされず、一時的にデータ収集が止まるだけです（個人サイトの規模であれば通常は超えません）。
